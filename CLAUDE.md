# Контекст проєкту для агента

Читай цей файл першим у кожній сесії. Він описує проєкт, конвенції та команди.

## Що це

«Тести на кавовій гущі» — жартівливі езотеричні тести. **Чистий фронтенд**: без бекенду,
без збірки, без фреймворків. Відкривається як статичні файли.

## Файли

| Файл | Роль |
|---|---|
| `index.html` | Розмітка, три екрани: `#screen-home`, `#screen-quiz`, `#screen-result` |
| `data.js` | Глобальний масив `TESTS` — увесь контент тестів |
| `app.js` | IIFE: навігація екранами, підрахунок балів, canvas із зорями |
| `styles.css` | CSS-змінні в `:root`, езотерична тема |
| `tests/` | Playwright-тести |
| `docs/evidence/` | Скріншоти-докази, на які посилаються коментарі агента |

## Структура даних

Кожен тест у `TESTS`:

```js
{ id, icon, title, subtitle,
  questions: [{ q, options: [{ t: "текст", r: "ключ_результату" }] }],
  results: { ключ: { emoji, title, text, advice, traits: [] } } }
```

Правила, які **не можна ламати**:

- у кожного питання рівно 4 варіанти;
- кожен `option.r` мусить існувати серед ключів `results`;
- у кожного результату є всі поля: `emoji`, `title`, `text`, `advice`, `traits`;
- варіанти перемішуються при показі (`shuffle`), тому тести не мають покладатися на порядок;
- вся видима користувачу мова — українська.

## Команди

```bash
npm install              # один раз, ставить Playwright
npx playwright install chromium
npm test                 # усі тести
npm run test:headed      # з видимим браузером
npm run serve            # http://localhost:8000
npm run evidence         # згенерувати скріншоти в docs/evidence/
```

## Конвенції коду

- Ванільний JS, без залежностей у рантаймі. Жодних фреймворків і бандлерів.
- Селектори через хелпер `$`, слухачі — делеговані де можливо.
- Кольори беруться з CSS-змінних у `:root`, не хардкодяться в правилах.
- Підтримується `prefers-reduced-motion` — будь-яка нова анімація мусить його поважати.
- Адаптив від 360px. Горизонтального скролу бути не може.
- Коментарі в коді — українською.

## Межі для агента

Агент **ніколи** не:

- мерджить PR (це робить людина);
- пушить у `main` напряму;
- змінює `.github/workflows/`, `.claude/`, налаштування репозиторію чи секрети;
- додає рантайм-залежності або систему збірки;
- чіпає більше файлів, ніж потрібно для тікета.
